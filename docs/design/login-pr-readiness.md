# 로그인 PR 통합 검증

기준: developer 5b5d05a, 로그인 원본 943e68b. 대상 브랜치는 developer다. 아직 병합되지 않은 feat/admin은 자동 포함하지 않았다.

## 보존한 팀 코드

- 회원가입 API 경로와 입력 계약, 회의실 목록 API 및 테스트.
- 예약·캘린더 컨트롤러/서비스 스켈레톤·DTO·모델·참석자·Slack 리마인더.
- 기존 예약·캘린더·관리자 화면, 메뉴, CSS, 임시 데이터.
- 이미 팀에 반영된 0001·0002·캘린더 0003 마이그레이션 원본.
- Gmail 앱 비밀번호 공백 정리 설정.

## 연결한 인증

- AuthProvider와 ProtectedRoute로 기존 팀 화면을 감싼다.
- 팀 components/AppLayout에 프로필 메뉴와 서버 세션 로그아웃을 추가한다.
- 로그인용 별도 AppLayout은 제거하여 공통 틀을 중복 운영하지 않는다.
- main.py는 기존 회원가입·회의실 라우터와 로그인·비밀번호·프로필 라우터를 함께 등록한다.
- 팀 회의실 API의 기존 DB 오류 상태 코드 500과 인증 API의 503을 구분해 기존 계약을 유지한다.
- 회원가입·예약 기능을 새로 구현하거나 기존 예약 스켈레톤에 HTTP 인증을 임의 연결하지 않는다.

## DB 변경

팀 캘린더가 이미 0003을 사용하므로 로그인 마이그레이션을 0004로 변경하고 0003 뒤에 연결한다. 신규 DB와 팀 developer의 0003 DB에서 upgrade head를 사용할 수 있다.

기존 로그인 전용 로컬 DB는 같은 0003 번호로 세션 테이블을 이미 생성했을 수 있다. 그 DB에 바로 upgrade head를 실행하면 중복 테이블 오류가 날 수 있다. 이 DB는 팀 0003 DB와 다른 스키마이므로 백업과 실제 테이블 확인 후 별도 전환해야 한다. 번호만 stamp하거나 DB를 삭제하지 않는다. 이번 검증은 기존 개발 DB를 변경하지 않았다.

## 리뷰할 정책 차이

기존 로그인 계획에는 차단 회원을 포함한 이메일 전체 고유 정책이 있다. 팀 회원가입의 차단 이메일 재가입 허용 정책과 다르며 이 PR은 전체 고유 정책을 유지한다. 가입 담당자가 이 변경을 리뷰해야 한다. 기존 중복 이메일이 있으면 0004는 데이터를 지우지 않고 실패한다.

## 검증 결과

- 별도 PostgreSQL 테스트 DB에서 백엔드 60개 테스트 통과. 팀 회의실 테스트 포함.
- 프런트 테스트 21개 및 TypeScript 검사·프로덕션 빌드 통과.
- 로그인 후 팀 캘린더 표시·예약/프로필 메뉴 보존·팀 레이아웃의 서버 로그아웃을 추가 검증.
- 별도 DB에서 팀 0003 → 로그인 0004, 0004 → 0003 → 0004 왕복 후 회원·회의실·예약·참석자 데이터 보존 확인.
- 실제 SMTP 전달과 전체 예약 기능 완성은 검증 범위가 아니다. 향후 developer 변경이 추가되면 다시 충돌·회귀 검증해야 한다.
