# 로그인 PR 범위와 확인 결과

기준 developer: 5b5d05a. 작업은 로그인·비밀번호 변경·비밀번호 찾기 및 필수 세션 관리로 한정한다. 이 문서는 이전 전체 통합·이메일 전체 고유 정책 설명을 대체한다.

## 변경하지 않은 담당자 영역

회원가입 users 모델·signup 서비스·auth DTO/API·mailer·기존 가입 테스트, 프런트 가입 화면·검증·signup API·공통 client를 developer 원본과 동일하게 유지했다. 회의실·예약·캘린더·관리자 화면과 업무 파일, 팀 AppLayout·layout.css, 팀 0001~0003 DB 이력도 그대로다. 핵심 27개 파일을 바이트 단위로 비교했다.

차단 이메일 재가입을 계속 허용하며 users_email_active_uniq를 유지한다. 로그인 때문에 가입 정책이나 users 제약을 변경하지 않는다.

## 내 기능의 수정

- 로그인은 현재 비차단 계정을 우선하며, 그 계정의 비밀번호가 틀려도 과거 차단 계정으로 넘어가지 않는다.
- 비밀번호 찾기는 현재 비차단 계정에만 인증번호를 보내고 증명을 user_id에 연결한다.
- 변경·찾기는 지정한 계정의 비밀번호와 세션만 바꾸며 같은 이메일의 과거 계정은 보존한다.
- 이름 수정·승인 CLI를 제거했다. /profile은 비밀번호 변경용 화면이다.
- 내 스키마·클라이언트·메일러·CSS·HTTP 보호를 별도 파일로 분리했다. 가입 API에 새 Origin/CSRF 정책을 씌우지 않는다.
- 로그인 마이그레이션 0004는 인증 테이블만 추가한다. 팀 migration과 users 인덱스를 바꾸지 않는다.

## 필요한 공통 연결 지점

main.py 라우터 등록·내 보안 미들웨어 설치, React App/main의 내 화면 연결, 설정·모델 등록·의존성·테스트 환경에 변경이 있다. 이는 코드 파일을 전혀 공유하지 않는다는 뜻이 아니며 다른 담당자의 업무 정책은 유지한다. 기존 팀 화면의 최종 인증·실데이터 연결은 추후 통합 범위다.

## 검증

백엔드 66개·프런트 23개 테스트, TypeScript 검사·프로덕션 빌드·내 백엔드 정적 검사를 통과했다. 별도 DB의 0003→0004→0003→0004 왕복에서 차단/재가입 이메일과 users 인덱스·팀 데이터를 보존한 것도 확인했다. 가입→승인 대기→외부 승인 모의→로그인→비밀번호 변경, 차단 이력/재가입 계정 선택, 과거 계정 증명 거절, 세션 만료·폐기·CSRF·동시 요청, 비밀번호 찾기 화면 흐름을 검증한다. 모든 검증 DB는 별도 _test DB이며 기존 개발 DB는 수정하지 않는다.

기존 로그인 전용 DB의 0003/0004와 전체 UNIQUE 인덱스는 이미 적용된 별도 이력일 수 있다. 파일 수정만으로 되돌아가지 않으므로 백업·별도 전환이 필요하다. 자동 삭제·stamp·기존 개발 DB migration은 하지 않았다.

PR 직전 대상 브랜치가 바뀌면 충돌과 회귀 테스트를 다시 확인한다. 원격 푸시와 PR 생성은 별도다.
